# Functional editor shell

`App.tsx` connects the full chapter 0–6 catalog and XOR lesson to the Worker. Interactive tensor execution happens in the Worker; asynchronous progress loading migrates legacy saves and revalidates marked changed-contract completions—including current-version saves—before the editor becomes available. `Canvas.tsx` only edits/displays JSON graphs. `Properties.tsx` handles node attributes; loss rendering reads `--accent` from the existing theme. `layout.css` contains layout rules only; `theme.css` is owned by the visual designer.

## Controls

- The component library is grouped by colour-coded family; each family folds independently. Related operations are ordered as pairs (add/subtract, multiply/divide, exponential/logarithm and square/square-root). A component that becomes available later is outlined and marked `NEW` across levels until the player first adds it; an existing browser's current library is used as the initial seen baseline so upgrades do not label every old component at once.
- Drag a palette component onto the canvas (or click/keyboard-activate it to add). Adding it, including through the expression tool, clears its `NEW` marker.
- Drag output to input, or onto a node's first empty input. Drag a connected input to rewire atomically; a rejected/cancelled connection preserves the original edge.
- Click a wire to remove it. Input/output interface nodes cannot be deleted.
- Click / Shift-click selects; Shift-drag blank space adds intersecting nodes to the selection. Clicking the background clears selection; middle-button dragging also pans. Drag blank space, or hold Space and drag, to pan. Wheel zoom anchors at the pointer.
- Delete, Ctrl/Cmd+C/V, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z. Clipboard is local to the editor, not the system clipboard.
- Expressions insert a laid-out fragment below existing nodes and connect it to the level output. Double-click a subgraph component to inspect its implementation read-only; Back returns.
- Tests/probes and training run in a module Worker. Training edits are locked until stopped or completed; pause retains optimizer state. DataPlot consumes live continuous-training prediction snapshots from progress events (250 ms throttle, plus final completion), while single-step mode retains its trace-based plot. Starting/resetting training or editing the graph clears old predictions; completion retains the final plot.
- Live values keeps scalar inputs editable and displays tensor fixtures read-only with previous/next case controls. Rank-zero shapes are shown as the localized word “scalar”/“标量” throughout player-facing copy, diagnostics and Properties, while graph JSON still stores them as `[]`. Outputs with domain meaning use stable semantic graph keys and localized labels (for example, `probabilities` is shown as “Probabilities” or “概率”); chapter 0 retains the conventional `y`. During verification, the selected shape and case follow each flattened test result, including `shape-N/` variants. Tensor nodes show shape, a short preview, and complete values in a tooltip. Element-wise binary nodes, including earned Subtract and Divide components, explicitly label mismatched input shapes as broadcasting on both the canvas and selected-node inspector. Selecting a canvas node adds a right-panel port inspector with every translated input/output name, current shape and value; each endpoint is probed separately so multi-output components remain accurate, while disconnected, optional-disconnected and error states stay explicit. Node previews and probes share `format-value.ts`: at most three significant digits, absolute values below 1e-4 displayed as zero, and compact scientific notation below 1e-3 or at/above 1e5 after rounding. Tooltips retain raw values. Shape-variant failures name the tested input shapes in the results table.
- Scalar lessons plot the target and explicit asymptotes without connecting across undefined jumps. Click/drag the plot, or focus it and use arrow/Home/End keys, to change the probe input; target and player tangents update continuously during a drag rather than waiting for release. Derivative lessons switch between the derivative curve and the original function with target/player tangents; single-output multivariable lessons label the differentiated input and hold the others fixed to show a one-dimensional partial-derivative slice. Level 1-10 instead shows a rotatable 3D function surface, with gradient vectors drawn in the input plane: the target is yellow, the player is cyan, and a match is green. This first gradient lesson deliberately omits loss, negative gradients and gradient descent. Switch between moving the input point and rotating the view; pointer drags and arrow keys control the selected mode. Chapter 3 then gives loss and descent separate playable visuals: display level 3-1 lets the player drag prediction `p` around a squared-loss bowl and compare it with target `t`; display level 3-2 lets them drag weight `w` while prediction, loss, the minimum, uphill gradient, target update, and circuit-produced update move live. The descent plot keeps its hidden squared-loss target fixed and updates `w` together with the supplied `∂L/∂p`, matching the lesson's local-backprop interface. Both plots support horizontal arrow keys, and a matching circuit point turns green. Softmax, LayerNorm, MSE, and cross entropy use row-selectable transformation traces tied to the current fixture and shape: each stage renders its values as bars and reports the reduction statistics used by the formula. MSE follows `p`, `t`, `p−t`, `(p−t)²`, and the last-axis Mean to connect display 3-1 with display 2-4. Cross entropy follows `p`, `ln(p)`, one-hot `t`, `t·ln(p)`, and the negative class sum for the selected row, while also reporting the mean loss across all rows. Elsewhere correct overlaps also turn green, the original function is light blue-grey, and asymptotes are dashed grey.
- Nonfinite wires tear open at their midpoint instead of becoming a solid warning band: positive infinity is warm, negative infinity cool and NaN fault pink. Level-complete unlocks stamp both player-built components and basic parts first exposed by the next lesson into place, then show one temporary component-family-coloured ring; the glyph has no permanent circular frame. The ring uses a fixed square box and centred uniform scaling so long glyphs cannot stretch it into an ellipse.
- Beginner learning links appear beside papers only when an advanced concept first enters the route, and select a Chinese or English source with the interface locale.
- Size (`|x|ₖ`) starts at axis −1 and accepts integer axis edits. It is available in the Mean lesson, whose shape-safe solution divides the last-axis Sum by the last-axis Size instead of hard-coding a width. Reshape exposes optional dimension ports d0–d3 only up to its target rank; wired shape overrides and wired range lengths are marked with arrows and disable their attribute field (disconnect to edit). Optional inputs do not produce missing-wire notes.
- Sum and reduce-max start with axis −1 and Keep dimensions enabled. Unsqueeze starts at axis −1; its axis editor accepts negative integers (valid range is checked against the input rank during compilation).
- Properties derives configurable-component fields dynamically from the component attribute schema and validates declared dimensions as constrained integers and booleans as actual boolean values. Fresh automatic learned modules hide their generated parameter input ports and show only data ports; lessons may provide placement defaults, such as regression's one-input/one-output Linear. A one-input-feature Linear treats rank-one `[N]` data as N scalar samples and flattens a one-feature output back to `[N]`, while normal vector/matrix Linear semantics are unchanged. Legacy nodes without `automatic_parameters` retain their explicit parameter ports and wiring. Shape diagnostics from expanded components map internal operation operands back through nested component boundaries, so errors identify the instance's public ports (for example Linear `x`/`w`) rather than internal matmul `a`/`b`.
- Save v9 idempotently migrates generic single-output `y` nodes in `savedGraphs` and `passedSolutions` to each lesson's semantic interface name, including saves produced by early v8 builds, while preserving node IDs, wiring, attributes, parameters, and editor `ui` data; chapter 0 keeps `y`. Momentum drafts from the former single-output contract gain a protected, initially disconnected `updatedMomentum` output; changed-contract revalidation revokes old completion while retaining the editable draft. Regression drafts with the old automatic Linear directly wired from `x` to MSE are narrowly repaired to `1→1`, preserving node IDs, wiring, other attributes, and `ui`; submitted passing solutions and unrelated Linear nodes are unchanged. Chapter-3 gradient drafts also rename their obsolete protected `t` input to `∂L/∂p` before changed-contract revalidation; the vector-gradient lesson removes its obsolete `w` input and incident wires because its new local VJP interface only needs `x` and the upstream gradient. This keeps revoked drafts editable while revoking incompatible completion. Players who had reached later chapter-3 content also receive access to the inserted `loss-intro` lesson without automatic pass credit or loss of their existing route. The reset introduced in v7 replaces 1-11 circuits from v2–v6 envelopes with the local backward contract for `z=w·x+b`: incompatible drafts, solutions, scores, and settings are removed and completion is revoked, while prior graduates retain `axes` and later access. The v5 `1-12`→`1-11` merge, chapter-1 reorder, and chapter-2 ID migration still run before that reset. Loading progress refreshes unlocks from already-passed lessons, so other new successors become available without replaying. New transpose nodes swap axes −2 and −1; legacy full permutations remain editable.

## State and persistence

`src/editor/state.ts` is a pure command reducer with graph/selection/viewport, snapshots for undo/redo, deterministic IDs, internal clipboard and cycle/port validation. A node drag previews locally and commits one move command. Pan/zoom is reducer state but is not graph history. Progress uses the engine's pure `applyResult`, including its best-score ordering. Only passing results unlock levels/components. Chapter 1 has eleven derivative lessons: 1-10 requires the named `∂a` and `∂b` outputs. In 1-11, the full context is `z=w·x+b`, `f=σ(z)`. The player receives `w`, `x`, and upstream gradient `∂f/∂z`, then emits `g·x`, `g·w`, and `g` as the named gradients for `w`, `x`, and `b`. The value of `b` is deliberately not an input because its local derivative is 1, and the player does not recompute Sigmoid. The normal gradient-view toolbar stays hidden on this multi-output lesson, but the completion modal reveals an independent full `z=w·x+b → f=σ(z)` forward graph. The engine differentiates that graph once and displays the first-order path from `f` through `z` to `w`, `x`, and `b`; it never differentiates the player's hand-built backward graph. The reveal marks `g=∂f/∂z` as the input/start of the player's circuit, highlights `z → w/x/b` as the multiply-and-add backward step the player just built, and labels `f → z` as the extra Sigmoid backward step expanded by the engine. The exact submitted graph is saved independently of unfinished edits in `passedSolutions`; passing again replaces that implementation. The palette combines allowed primitives, previously built components and level presets into the family groups, excluding forbidden components and the current lesson's output. Par and optional feature-unlock messages appear on completion.

Graphs include positions in `node.ui`. `src/storage.ts` validates versioned localStorage data and catches unavailable/corrupt storage. A trailing throttle writes edits every 400ms, with a pagehide/unmount flush. A failed save does not crash the page; language persistence is attempted independently even when writing progress fails. Read-only component inspection also disables undo/redo on the parent graph. Probe requests discard results when the graph or player-registry revision changes. The editor and canvas share `buildPlayerRegistry`; registry changes are sent to the Worker with `syncProgress` before compilation. Component inspection displays the player's passed graph, including nested implementations.

## Localization

Use `const t = createTranslator(locale)` then `t('ui.report', {step, loss, accuracy})`. Numeric interpolation uses `Intl.NumberFormat`; plural dictionaries select via `Intl.PluralRules` and a `count` parameter. `translateDiagnostic(locale, error)` maps engine codes, without displaying exception prose. `MathText` accepts `$…$` inline formulas, standalone `$$…$$` display formulas, braced `^{…}`/`_{…}` scripts, and stacked `\\frac{numerator}{denominator}` fractions inside either form.

Add `src/locales/<language>.json` with the same flat keys as English and register its import in `src/i18n.ts`. Locale names are derived from the locale registry. Missing messages fall back to English and warn in development. Tests check Chinese/English key parity. Component names use `components.<name>` (not `component.*`); shared port labels use `ports.<port>`. Use `translatePort(t, component, port)` for port descriptions: `ports.<component>.<port>` overrides the shared label, and unknown user-defined ports retain their identifiers. For example, `one_hot.k` means class count, while attention's `k` means key. Canvas port symbols remain compact identifiers, with translated descriptions in tooltips.

## Validation boundaries and remaining UI polish

Builds and Node tests do not prove pointer interactions, accessibility or WebGPU behavior in an actual browser, so visual review is still required. Rejected connections shake their target node; pass and overflow effects respect reduced-motion preferences where applicable. Large graphs have fit-to-view but no virtualization or minimap. Inspecting shape-dependent generated subgraphs can fail without concrete input shape context; it reports an error instead of guessing shapes. Canvas node feet currently show the first output port and a bounded numeric preview; the selected-node inspector probes all visible endpoints, and single-step training separately shows parameter updates. The formal scalar/derivative lessons use scalar inputs; the XOR preview uses batches.
